What JSON contains the remaining parent count, child count and parent label after the replacement?

Assumptions:
- Run in a fresh PHP process using only the displayed files and inputs.
- This fixture uses SQLite with foreign-key enforcement enabled. All setup statements succeed. The behavior asked about is SQLite-specific; it is not a general claim about every database’s upsert syntax.

FILE: main.php [complete-file]
<?php

$pdo = new PDO('sqlite::memory:');
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$pdo->exec('PRAGMA foreign_keys = ON');
$pdo->exec('CREATE TABLE parents (id INTEGER PRIMARY KEY, label TEXT NOT NULL)');
$pdo->exec('CREATE TABLE children (parent_id INTEGER REFERENCES parents(id) ON DELETE CASCADE)');
$pdo->exec("INSERT INTO parents VALUES (1, 'old')");
$pdo->exec('INSERT INTO children VALUES (1)');

$pdo->exec("INSERT OR REPLACE INTO parents VALUES (1, 'new')");

$parents = (int) $pdo->query('SELECT COUNT(*) FROM parents')->fetchColumn();
$children = (int) $pdo->query('SELECT COUNT(*) FROM children')->fetchColumn();
$label = $pdo->query('SELECT label FROM parents WHERE id = 1')->fetchColumn();

A. [1,1,"new"]

B. [1,1,"old"]

C. [0,0,false]

D. [1,0,"new"]

ANSWER AND REVIEW EVIDENCE
Correct: D [cascade]
SQLite REPLACE resolves this primary-key conflict by deleting the existing row and inserting the supplied row. The deletion’s foreign-key cascade is real even though a parent with the same ID exists again afterward.
Trace: The child disappears when old parent 1 is deleted. The subsequent new parent 1 has label new and no child rows.

A: REPLACE deletes the conflicting row before inserting, so the cascade removes its child.
Misunderstanding tested: Treating replacement as an in-place update that preserves dependent rows.

B: The conflict policy is REPLACE rather than IGNORE; the parent is replaced.
Misunderstanding tested: Confusing conflict-ignore behavior with replacement.

C: The conflicting parent is deleted, but the new parent row is then inserted successfully.
Misunderstanding tested: Tracing only the deletion phase of the replacement.

D: Deleting the old parent cascades to its child, and inserting the new parent does not recreate that child.

The existing per-chunk encoding inserts padding in the middle of the stored data. Which replacement block stores QUJDRA== for the chunks A, BC and D?

Assumptions:
- Run in a fresh PHP process using only the displayed files and inputs.
- The chunks form one logical byte sequence and may split base64 groups anywhere. The function must write one continuous base64 encoding to the underlying regular file without concatenating all chunks in memory. All local I/O and filter operations succeed. The final read opens the file independently, without any filter.

FILE: main.php [complete-file]
<?php

$chunks = ['A', 'BC', 'D'];
$path = __DIR__ . '/encoded.txt';
$handle = fopen($path, 'w+b');

foreach ($chunks as $chunk) {
    fwrite($handle, base64_encode($chunk));
}

fclose($handle);
echo file_get_contents($path);

A. foreach ($chunks as $chunk) {
    fwrite($handle, base64_encode($chunk));
}

B. foreach ($chunks as $chunk) {
    $filter = stream_filter_append($handle, 'convert.base64-encode', STREAM_FILTER_WRITE);
    fwrite($handle, $chunk);
    stream_filter_remove($filter);
}

C. $filter = stream_filter_append($handle, 'convert.base64-encode', STREAM_FILTER_READ);

foreach ($chunks as $chunk) {
    fwrite($handle, $chunk);
}

stream_filter_remove($filter);

D. $filter = stream_filter_append($handle, 'convert.base64-encode', STREAM_FILTER_WRITE);

foreach ($chunks as $chunk) {
    fwrite($handle, $chunk);
}

stream_filter_remove($filter);

ANSWER AND REVIEW EVIDENCE
Correct: D [continuous-filter]
Base64 encoding has cross-chunk state. A single write filter retains incomplete groups between writes; final removal flushes the last group into the underlying file.
Trace: The filter processes ABC as a complete group and D as the final padded group, storing QUJDRA==. Resetting the encoder per chunk produces separate padded segments.

A: Each call finalizes and pads its own independent encoding.
Misunderstanding tested: Assuming concatenating independently padded encodings equals encoding the concatenated input.

B: Removing the filter after every chunk flushes and pads each separate sequence.
Misunderstanding tested: Assuming changing to a filter helps even when its state is reset at every chunk.

C: A read filter does not encode writes, and the later independent file read has no filter.
Misunderstanding tested: Applying the transformation to the wrong direction of the stream.

D: One write filter carries partial groups across chunks and flushes its final padding only when removed.
