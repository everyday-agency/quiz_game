Structure and authoring
The pilot's structure is retained: stable ID and revision; technology and
collection; single-choice response type; topic/subtopic and objective; format;
difficulty with rationale; explicit prerequisites; PHP versions and runtime
conditions; assumptions and named source files; four stable option IDs; one
correctOptionId; a rationale and realistic misconception for each wrong option;
summary and execution trace; references and validation status/evidence.

Files are authored individually in ../php-expansion/authoring/batch-01.mjs
through batch-06.mjs. The record helper supplies schema boilerplate only. It
never expands a snippet into several question templates. Accepted full records
are in ../js/php-expansion/batches/batch-01.mjs through batch-06.mjs.

There are 502 questions with 517 named complete PHP files, including 14 multi-file
questions. The other 98 are explicit requirements/document-backed scenarios.
Replacement expressions and blocks are isolated fragments within a stated host
file; the harness substitutes them into that host before checking them. The
retained pilot's existing fragment/file distinctions remain unchanged. Sources
have four-space indentation, multiline declarations/blocks, and literal
whitespace preserved. Source-token checks avoid mistaking braces inside strings
or comments for compressed PHP blocks. Intentional errors are identified by the
question and checked as expected errors rather than silently repaired.

Editorial and duplicate analysis
All 600 have an authoring-assistant review against the same rubric: a specific
objective; sufficient premises; one keyed answer; plausible misconceptions;
PHP evidence or an explicit documented contract; per-choice explanations;
appropriate difficulty/prerequisites; readable source; and a distinct reasoning
path. The reviewer is explicitly identified as NOT independent.

Similarity screening compared new items to earlier accepted batches, the 20
pilot items and the archived PHP bank. It produced 474 candidate pairs; 499
pair reviews were documented after additional manual comparisons. Shared PDO
setup, exception syntax or domain vocabulary can be retained when the actual
mechanism differs. For example, fetchColumn advancing a whole row is distinct
from FETCH_LAZY sharing a row-view object. These comparisons and reasons are
recorded per pair. Similarity thresholds cannot prove semantic originality.
Manual review caught overlaps that the lexical heuristic missed, including a
second proposed strtr test; that draft was replaced before acceptance.

No new option contains the screened stock phrases “suppress every failure”,
“replace ... with a comment”, “keep the relevant mechanism” or “exercise the
shown path”. No new question uses the artificial “Reasoning check” or “Evidence
to inspect” padding. The archived current 300 contain those stock phrases in
123 questions and padding in 189. The previous audit demonstrated that stock
wording could reveal a key without understanding the source; eliminating those
phrases addresses that specific defect, not every possible linguistic cue.

Length remains a review signal: 180/600 correct answers are uniquely longest;
504/600 questions have any uniquely longest choice, so selecting it is correct
on 180/504 (35.7%) of that subset. This residual association must not be described
as proof of wording neutrality. Three >1.45x length flags (0010, 0486, 0515) were
reviewed: each is a literal output consequence, not explanatory padding. Correct
answers are uniquely shortest in 43 questions. Do not add filler to equalize
lengths. Independent stem-hidden review should test whether specificity,
grammar or technical completeness gives away other keys, especially reasoning
items. Learner calibration has not been performed.

Authored positions 1–4 contain 123/157/172/148 keys. The application shuffles
options; it does not expose that source ordering as a strategy. In the final
620-item browser Learn run, displayed positions contained 156/150/151/163 keys,
with grading and explanations mapped by identity. These are observed counts,
not an enforced answer-length or position-balancing template.

Concrete improvements over old patterns
- Old PQ-001 includes choices claiming that runtime “skips the shown branch”
  and appends generic reasoning padding. New PHP-E26-0001 requires the exact
  signed quotient and remainder. Its alternatives correspond to floor division,
  nonnegative remainder and ordinary floating-point division.
- Old template-based test choices often say to “exercise the shown path”. New
  PHP-E26-0081 offers four legitimate input/output tests, but only a leading
  removed array element exposes the JSON list-shape defect.
- PHP-E26-0341 compares stream-filter lifetimes and read/write directions using
  the same three byte chunks. Every candidate is checked in the displayed host;
  choosing the answer requires understanding encoder state across writes.
- PHP-E26-0591 separates strict Base64 decoding from canonical spelling. Its
  adversarial input exposes a realistic validation misunderstanding; a test of
  an already canonical or plainly invalid string would miss the defect.
These full records and 16 others are in EDITORIAL_REVIEW_20.txt. This sample is
for independent critique, not a claim that 20 reviews certify all 600 records.
