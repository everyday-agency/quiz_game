Your next mission is to create **600 entirely new Laravel Specialist examination questions**, using the same quality standards and infrastructure.

Work autonomously through all 600 questions without requesting approval after each batch.

However, generate, validate, and save the work in **six batches of 100 questions**. Do not produce all 600 as one unvalidated generation step.

Use the six formats established in the PHP Engineer bank:

2. Debugging

4. Implementation choices
5. Testing and regression detection
6. Application architecture

Include Foundation, Intermediate and Advanced questions.

Difficulty must be based on the reasoning required, not merely on obscure Laravel features.

Questions should increasingly resemble situations an actual Laravel developer encounters when maintaining a real application.

## 4. Question Quality Requirements

Every question must have:

- One specific, meaningful learning objective.
- Four plausible answer options.
- Exactly one objectively defensible correct answer.
- Accurate explanations for all four alternatives.
- Readable, properly formatted code where applicable.
- Complete context and clearly stated assumptions.
- Appropriate prerequisites.
- Relevant Laravel/PHP documentation references.
- Stable ID and revision metadata.
- Technical validation evidence.

Do not generate questions by repeatedly changing variable names, numbers, or superficial scenarios.

Avoid:

- Obvious distractors.
- Repetitive question templates.
- Correct answers identifiable through length or wording.
- Assumptions that reveal the answer.
- Questions that reproduce their own solution in the displayed code.
- Unnecessarily obscure trivia.
- Incorrect Laravel methods or fabricated framework behavior.

When testing code behavior, validate it against a real compatible Laravel installation where feasible.

PHP syntax checks alone are insufficient to validate Laravel framework behavior.

For scenarios that cannot reasonably be executed, use documented-contract validation and label them explicitly. Never invent test results.
